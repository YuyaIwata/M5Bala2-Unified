# キーボード操作コンテナ

ROS 2 経由で Bala2 をキーボードから操作します。

## 使い方

エージェントを起動しておきます。

```bash
container run --rm --name uros-agent -p 8888:8888/udp \
  microros/micro-ros-agent:jazzy udp4 --port 8888 -v4
```

イメージをビルドします（初回のみ）。

```bash
cd tools/teleop
container build -t bala2-teleop -f Containerfile .
```

操作を開始します。`-t` が必須です（キー入力に端末が必要）。

```bash
container run --rm -it bala2-teleop
```

## キー割り当て

| キー | 動作 |
| ---- | ---- |
| `w` / `s` | 前進 / 後退 |
| `a` / `d` | 左旋回 / 右旋回（反時計回り / 時計回り、REP-103 準拠） |
| `space` | 走行停止（バランスは維持） |
| `e` | 制御を有効化 |
| `q` | 制御を無効化 |
| `,` / `.` | 前後の速度を下げる / 上げる |
| `<` / `>` | 旋回速度を下げる / 上げる |
| `Ctrl-C` | 無効化して終了 |

画面下部に状態が表示されます。

```
RUN   angle  +1.25  pwm  +142  yaw   +12.3  cmd +0.30/+0.00  scale 0.30/0.30
```

`NO LINK` は `/control` が 1 秒以上届いていない状態です。エージェントが起動しているか、機体の LCD が `ROS ok` になっているかを確認してください。

## 設計上の判断

**`teleop_twist_keyboard` を使っていません。** 2 つ理由があります。

第一に、あちらは `/enable` を扱えません。この機体は制御の有効化が別トピックになっており、走行指令だけでは動きません。

第二に、`teleop_twist_keyboard` は最後の `Twist` を保持し続けます。倒立振子では、キーから手を離しても走り続けることになり危険です。本ノードは**最後のキー入力から 0.7 秒で速度指令をゼロに戻します**。キーを押し続けている間は端末のオートリピートで維持され、離せば止まります。機体側にも 500ms の `cmd_vel` タイムアウトがあり、二重の保護になっています。

`/enable` は 3 回連続で送信します。探索が落ち着く前の 1 通が失われることがあり、有効化の取りこぼしは機体の故障と区別できないためです。

終了時（`Ctrl-C`）は走行停止と無効化を送ります。

## 別コンテナからの DDS 通信について

エージェントとテレオペを別コンテナで動かしても通信できます。`apple/container` の既定ネットワーク（192.168.64.0/24）でマルチキャストによる DDS 探索が機能するため、追加設定は不要です。

実測では、テレオペコンテナから `/control` を 48.5Hz で受信し、`/enable` の送信も機体に届きました。

うまく見えない場合は、同一コンテナ内で実行する方法もあります。

```bash
container exec -it uros-agent bash -lc \
  'source /opt/ros/jazzy/setup.bash && python3 /path/to/bala2_teleop.py'
```
